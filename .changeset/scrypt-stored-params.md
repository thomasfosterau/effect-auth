scrypt `verify` now checks the N, r and p it reads from a stored hash before it runs the KDF, and refuses a set outside the limits with a `HashingError` rather than a defect or a boolean. N must be a power of two with 2 ≤ N ≤ max(2^20, the configured cost). r must be an integer from 1 to max(32, the configured block size), and p an integer from 1 to max(16, the configured parallelization). The memory a derivation needs, `128 * r * (N + p + 2)`, must not exceed max(256 MiB, the memory the configured parameters need), so the hasher's own hashes always verify while a crafted hash cannot request gigabytes. A synchronous throw from Node's `crypto.scrypt` is now also a `HashingError`. `needsRehash` returns true for a hash `verify` would refuse, and for one whose r or p is below the configured value, as it already did for N. `hash` now applies the same checks to the configured cost, block size and parallelization, and fails with a `HashingError` for a configuration its own `verify` would refuse (for example `blockSize: 0`, which Node accepts), instead of writing a hash that can never verify. A non-finite configured value cannot lift the caps.
