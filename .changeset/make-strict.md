`Http.make` takes `strict`, an opt-in for an app that wants `make` to fail at startup whenever it cannot check the `services` build. With `strict: true`, `make` throws `ServicesBuildPendingError` when the `services` build has not finished after `make` has run it synchronously: a build that waits on asynchronous work (a database connection, `Effect.promise`), on a merged layer that yields, on a forked fiber, or, when the build fails, on a finalizer that does asynchronous work. The error's message names `Http.makeAsync`, which waits for such a build. `make` interrupts the build and releases what the build acquired, as far as that runs synchronously, then throws; a finalizer that does asynchronous work, and the whole release of a build in an uninterruptible step that awaits (an `Effect.acquireRelease` acquire), finish after `make` has thrown. When the build fails on its own account, as a step that fails while a finalizer it runs awaits does, `make` logs that failure with `Effect.logError` once the build ends. A build that finishes synchronously is unaffected: `make` throws the startup errors or the build's own failure, or returns the handler. Without the option, `make` returns for an unfinished build, and the startup checks run when the build finishes, failing the handler's build. `Http.makeAsync` ignores the option. `ServicesBuildPendingError` is exported from the package root and as `Http.ServicesBuildPendingError` (#416).
