`Http.make` runs the `services` build until it finishes, and no further. A fiber the build forks with `Effect.forkChild` is interrupted when the build finishes, so one that has not started by then never runs. A fiber forked into the layer's scope (`Effect.forkScoped`) keeps running under the default scheduler after `make` returns, and stops on `dispose`; a fiber forked with `Effect.forkDetach` keeps running, and `dispose` does not stop it. Any failure of a `services` build that finishes while `make` runs makes `make` throw, so the app fails to start: the failure's error, or for a defect the defect itself, as `Effect.runSync` throws. An example is the OIDC layer's `ClientAddressConfigError` for dynamic registration with no address source. `make` releases what the build acquired, then throws: a finalizer that does asynchronous work finishes after `make` has thrown, and a finalizer that fails is logged as an error. A `services` build that waits on asynchronous work, on a merged layer that yields or runs past Effect's per-slice operation budget, or, when it fails, on a finalizer that does asynchronous work, finishes after `make` returns. Its failure then fails the handler's build instead, and every request rejects with it; `Http.makeAsync` rejects at startup for those builds (#402). The startup errors and the release log name both `Http.make` and `Http.makeAsync`.
