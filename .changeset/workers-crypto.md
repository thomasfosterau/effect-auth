The core's crypto now runs on Cloudflare Workers (#748). Workers apps gain working JWTs and OIDC: ES256, `JwtService`'s default, failed to sign and verify on every compatibility date (workerd's `node:crypto` rejects a `KeyObject` beside `dsaEncoding` with `ERR_INVALID_ARG_TYPE`), which broke `JwtService`, the OIDC provider's `id_token`s, ES256 `id_token` verification in `OAuthService` and `appleClientSecret`; `signJws` and `verifyJws` now pass the PEM or the JWK instead, and sign and verify exactly as before on Node (the same tokens, the same refusals). `generateJwsKeyPair`, and so `JwtService`'s first key, failed from compatibility date 2025-12-03, where workerd's JWK export carries absent members as `undefined`; those are dropped. Apps on a compatibility date before 2024-09-23 also gain the default PBKDF2 and scrypt password hashers, AES-256-GCM (`aes256GcmCipher`, the session cookie cache) and the WebAuthn signature checks, which read the `Buffer` global that `nodejs_compat` sets only from that date and now import it from `node:buffer`. The README's new Runtimes section states the supported floor: `nodejs_compat` and a compatibility date of 2023-01-01 or later, tested inside a real workerd.
