Attribute, metadata and claims bags are typed as JSON (#443). The core exports `Json` and `JsonObject` (Effect's `Schema.Json` / `Schema.JsonObject`, as types and as schemas), and `Attributes` is now `JsonObject` (was `Record<string, unknown>`). The same type replaces `Record<string, unknown>` for user and session `attributes` and every `sessionAttributes` option, API-key, organization, OIDC-client and one-time-token `metadata`, JWT claims (`definePayload`, `sign`'s extra claims, `verify`, `RemoteJwksVerifier.verify`) and JWKs (`JwtKeyPair.publicKeyJwk`, `Jwks.keys`), Google One Tap `claims`, `OAuthUserInfo`'s extra fields and `mapProfile`'s input, the OIDC provider's `userinfo` and metadata documents, and `Messages` params; the HTTP tier's `Attributes`, `ClaimsView` and `JwksView` schemas validate JSON. In effect-auth-drizzle, the attribute columns are `$type<Auth.JsonObject>()` and `defineSchema`'s `attributes` mappings expect that type. The stores already persisted these bags as JSON, so nothing changes at runtime for JSON values.

Migration: a value in one of these bags must be JSON: a string, a number, a boolean, `null`, or arrays and objects of those. Convert anything else before it goes in: a `Date` to an ISO string or epoch milliseconds, a class instance to a plain object, and leave a key out instead of setting it to `undefined`; functions, `Map`s, `Set`s and `bigint`s have no JSON form. A value read out of a bag is now `Json` rather than `unknown`, so narrow it (`Predicate.isString`, …) before use. An `interface` is not assignable to `JsonObject` (it has no index signature); declare the bag's shape with a `type` alias instead. A drizzle table your app defines writes `jsonb().$type<Auth.JsonObject>()` (or `json()` / `text({ mode: "json" })`) for its attribute bag. `./testing`'s `viewerLayerAs` default `toUser` now copies only the viewer's JSON-valued fields into `attributes`.
