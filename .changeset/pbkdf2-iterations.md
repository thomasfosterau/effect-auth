`pbkdf2Hasher` takes an `iterations` option, as `scryptHasher` takes `cost`, and `PasswordHasher.layer` forwards it: `pbkdf2Hasher({ iterations })` and `PasswordHasher.layer({ iterations })`. The default is unchanged at 600,000 iterations (the OWASP figure for PBKDF2-HMAC-SHA256), so existing callers and stored hashes behave exactly as before. The count must be an integer from 1 to 2147483647, Node's limit for `crypto.pbkdf2`. `hash` refuses any other value with a `HashingError` rather than writing a hash `verify` cannot read. `needsRehash` compares stored hashes against the configured count, so a hash made at a lower count is upgraded on the next successful sign-in. `verify` still reads the count from the stored hash, up to a cap of 5,000,000 (or the configured count, if higher) above which it refuses the hash before running PBKDF2. Lower counts are for tests and other cases where cost is not the point; keep the default in production (#290).
