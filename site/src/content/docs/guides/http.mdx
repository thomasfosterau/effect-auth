---
title: HTTP Protocol & Framework Mounting
description: Serve the whole auth surface as a mountable web handler, with a typed client derived from the same contract.
---

The HTTP layer is a typed `effect/unstable/httpapi` contract (`Http.AuthApi`)
that is the single source of truth for the protocol. From it, effect-auth
derives the server, a typed Effect client, and an OpenAPI 3.1 document.

## Mount the handler

`makeAuthWebHandler` turns the contract + your service layer into a standard
Web `Request => Response` function:

```ts
import { Layer } from "effect";
import * as Auth from "effect-auth";

declare const services: Layer.Layer<Auth.Http.AuthServices>;

const { handler, dispose } = Auth.Http.makeAuthWebHandler({
  services,
  prefix: "/api/auth",
  cookie: { name: "conduit_session", secure: true },
  trustedOrigins: ["https://app.example.com"],
});
```

Mount `handler` anywhere a `Request => Response` fits:

```ts
// Bun
Bun.serve({ fetch: (request) => handler(request) });

// Next.js route handler (app/api/auth/[...path]/route.ts)
export const GET = handler;
export const POST = handler;

// SvelteKit (src/routes/api/auth/[...path]/+server.ts)
export const fallback = ({ request }) => handler(request);
```

`services` is a `Layer` providing the core services (`SessionManager`,
`AuthLifecycleService`, stores, `Hooks.Default`, ...). Optional features
(magic link, organizations, OIDC provider, ...) switch on when you merge
their layers in — their endpoints answer `404` until then.

## Cookies

- The session cookie (default `conduit_session`) is httpOnly, SameSite=Lax.
- `cookie.cache` enables an HMAC-signed session-data cookie so authenticated
  requests can be served without a session-store read for a short window.
- `cookie.lastLoginMethod` writes a page-readable `${name}_last_method`
  cookie on every sign-in (`"email-password"`, `"magic-link"`, `"sso"`, ...)
  so login pages can highlight the user's previous method.
- `multiSession` keeps several signed-in accounts per browser; switch with
  `POST /multi-session/set-active`.

## CSRF

State-changing requests with an `Origin` header must match the request's own
origin or an entry in `trustedOrigins`; anything else is rejected with `403`
before reaching a handler.

## OpenAPI docs

```ts
Auth.Http.getOpenApiSpec(); // OpenAPI 3.1 document
```

With `makeAuthWebHandler({ docs: true })`, `GET {prefix}/openapi.json`
serves the document and `GET {prefix}/reference` a Scalar reference UI.

## Typed clients

For Effect applications, derive a fully typed client from the same contract
(tagged errors in the Effect error channel):

```ts
import { Effect } from "effect";
import { FetchHttpClient } from "effect/unstable/http";
import * as Auth from "effect-auth";

const program = Effect.gen(function* () {
  const client = yield* Auth.Http.makeAuthClient("https://app.example.com/api/auth");
  const result = yield* client.auth.signIn({
    payload: { email: "user@example.com", password: "..." },
  });
  return result.user;
}).pipe(Effect.provide(FetchHttpClient.layer));
```

For browser apps, [`@effect-auth/client`](https://www.npmjs.com/package/@effect-auth/client)
is a small dependency-free client with an observable session store and
React/Svelte/Vue bindings:

```ts
import { createAuthClient } from "@effect-auth/client";

const client = createAuthClient({ baseUrl: "/api/auth" });
await client.signIn({ email, password });
```

```tsx
import { useSession } from "@effect-auth/client/react";

function Navbar() {
  const { data, isPending } = useSession(client);
  return data ? <b>{data.user.email}</b> : <a href="/login">Sign in</a>;
}
```
