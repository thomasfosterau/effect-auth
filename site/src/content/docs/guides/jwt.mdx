---
title: JWT & JWKS
description: Issue asymmetrically signed JWTs so downstream services can verify sessions without a round trip.
---

The JWT module mints short-lived, asymmetrically signed tokens (ES256 by
default, EdDSA optional) for authenticated users, and publishes the matching
public keys as a JWKS document. Downstream services verify tokens locally —
no shared secret, no call back to the auth server. Implemented with
`node:crypto` only.

## Enable

```ts
import { Layer } from "effect";
import * as Auth from "effect-auth";

declare const jwtKeyStore: Auth.JwtKeyStoreShape;

const jwt = Layer.mergeAll(
  Auth.JwtService.layer({
    issuer: "https://app.example.com",
    expiresIn: 15 * 60 * 1000, // default 15 minutes
    algorithm: "ES256", // or "EdDSA"
    definePayload: (user) => ({ role: user.attributes["role"] }),
  }),
  Layer.succeed(Auth.JwtKeyStore)(jwtKeyStore),
);
```

Signing keys are generated lazily on first use and persisted through the
`JwtKeyStore` (public JWK + PKCS#8 private PEM — encrypt at rest in
production).

## Endpoints

- `GET /token` (session-authenticated) → `{ token, expiresAt }`
- `GET /jwks` → the JWKS document for verifiers

## Verifying downstream

Any JOSE library works against the JWKS. Within Effect, the service itself
verifies too:

```ts
import { Effect } from "effect";
import * as Auth from "effect-auth";

declare const service: Auth.JwtServiceShape;

const check = (token: string) =>
  Effect.gen(function* () {
    const claims = yield* service.verify(token); // signature, exp, iss, aud
    return claims["sub"];
  });
```

## Shared keys with the OIDC provider

The [OIDC provider](/guides/oidc-provider/) signs its `id_token`s with the
same `JwtService`, so one JWKS (also served at `/.well-known/jwks.json`)
verifies both plain user JWTs and OIDC id_tokens.
