---
title: "Migration: User Model v2"
description: Upgrade store implementations to the first-class User model (email, emailVerified, name, image, timestamps).
---

Early versions of effect-auth modelled users as an id plus an opaque
`attributes` bag — application code read `user.attributes.email`. The current
model promotes the common identity fields to first-class, schema-validated
columns:

```ts
import * as Auth from "effect-auth";

declare const user: Auth.User;

user.id; //            string
user.email; //         string — unique, normalized lowercase
user.emailVerified; // boolean
user.name; //          string | undefined
user.image; //         string | undefined
user.createdAt; //     Date
user.updatedAt; //     Date
user.attributes; //    Record<string, unknown> — everything app-specific
```

`User`, `Session`, and `SessionWithUser` are `Schema` structs, so one
definition provides the TypeScript type, runtime validation, and the JSON
encoding used by stores and the HTTP layer.

## What breaks

- **Reading identity from attributes.** `user.attributes.email`,
  `attributes.emailVerified`, `attributes.name`, and `attributes.picture`
  are now first-class fields. App-specific data (usernames, roles, phone
  numbers, wallet addresses) still lives in `attributes`.
- **Store shapes.** Every user row needs the new columns, and a few store
  interfaces gained methods (below).

## Store implementer checklist

1. **New user columns** — add `email` (unique index, store lowercase),
   `email_verified`, nullable `name` and `image`, and `created_at` /
   `updated_at` timestamps. Move any duplicated values out of the
   attributes JSON.

2. **`SessionStore.listByUserId`** — the session store now lists a user's
   sessions (powers `listSessions`, `revokeOtherSessions`, and the
   `/sessions` endpoints):

   ```ts
   listByUserId: (userId) =>
     Effect.sync(() => [...sessions.values()].filter((s) => s.userId === userId)),
   ```

3. **`CreateUserInput` shape** — `EmailPasswordStore.createUser` receives
   `{ email, name?, image?, attributes? }` and must return a full
   `Auth.User` (set `emailVerified: false`, stamp both timestamps).

4. **`resendVerification(userId, email)`** — the email-verification service
   re-sends by user id _and_ email, so implementations no longer look the
   user up by email themselves.

5. **Password hashes stay separate** — `getPasswordHash` /
   `setPasswordHash` on `EmailPasswordStore` (nullable: OAuth-created users
   have no password until `setPassword`).

## Example: SQL columns

```sql
ALTER TABLE users ADD COLUMN email TEXT NOT NULL DEFAULT '';
ALTER TABLE users ADD COLUMN email_verified INTEGER NOT NULL DEFAULT 0;
ALTER TABLE users ADD COLUMN name TEXT;
ALTER TABLE users ADD COLUMN image TEXT;
ALTER TABLE users ADD COLUMN created_at INTEGER NOT NULL DEFAULT 0;
ALTER TABLE users ADD COLUMN updated_at INTEGER NOT NULL DEFAULT 0;

-- Backfill from the old attributes JSON, then:
CREATE UNIQUE INDEX users_email ON users (email);
```

Backfill `email` from `attributes->>'email'`, lowercase it, then delete the
duplicated keys from the JSON.

If you use `@effect-auth/sql`, its schema already matches the v2 model —
run its migrations instead of hand-rolling the DDL.
