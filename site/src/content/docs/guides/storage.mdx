---
title: Storage Backends
description: Implement the store interfaces yourself, use the KV-backed layers, or drop in @effect-auth/sql.
---

effect-auth is storage-agnostic: every module declares small store
interfaces (`SessionStore`, `EmailPasswordStore`, `MagicLinkStore`, ...) and
you decide what backs them. Three approaches, mixable per store:

## 1. Implement the interfaces directly

A store is a plain object of Effect-returning methods — implement it against
anything:

```ts
import { Effect, Layer } from "effect";
import * as Auth from "effect-auth";

const sessions = new Map<string, Auth.Session>();

const sessionStore: Auth.SessionStoreShape = {
  create: (s) => Effect.sync(() => (sessions.set(s.id, s), s)),
  get: (id) =>
    Effect.suspend(() => {
      const s = sessions.get(id);
      return s
        ? Effect.succeed(s)
        : Effect.fail(new Auth.SessionNotFoundError({ message: "not found", sessionId: id }));
    }),
  update: (s) => Effect.sync(() => (sessions.set(s.id, s), s)),
  delete: (id) => Effect.sync(() => void sessions.delete(id)),
  deleteByUserId: (userId) =>
    Effect.sync(() => {
      for (const [id, s] of sessions) if (s.userId === userId) sessions.delete(id);
    }),
  listByUserId: (userId) =>
    Effect.sync(() => [...sessions.values()].filter((s) => s.userId === userId)),
};

const layer = Layer.succeed(Auth.SessionStore)(sessionStore);
```

## 2. KV-backed layers for the ephemeral stores

The `KeyValueStores` module ships layers for the short-lived stores (OAuth
state, WebAuthn challenges, rate limits, email-verification and
password-reset tokens, magic links, email OTPs, pending two-factor
challenges) over `effect/unstable/persistence`'s `KeyValueStore` — so one
choice of backend (in-memory, file system, Redis) covers them all:

```ts
import { Layer } from "effect";
import { KeyValueStore } from "effect/unstable/persistence";
import * as Auth from "effect-auth";

// Every ephemeral store at once...
const ephemeral = Auth.layerKV.pipe(Layer.provide(KeyValueStore.layerMemory));

// ...or pick individual ones:
const magicLinks = Auth.MagicLinkStoreKV.pipe(Layer.provide(KeyValueStore.layerMemory));
```

Swap `layerMemory` for the file-system or Redis `KeyValueStore` layer in
production.

## 3. `@effect-auth/sql` for the persistent stores

The `@effect-auth/sql` package implements the persistent stores (users,
sessions, credentials, OAuth accounts, roles, two-factor records, ...) over
`effect/unstable/sql`'s `SqlClient`, so it works with any SQL driver layer
(pg, mysql, sqlite, Cloudflare D1, ...):

```ts
import { Layer, Effect } from "effect";
import * as Sql from "@effect-auth/sql";

declare const SqlClientLayer: Layer.Layer<never>; // your driver layer

const stores = Sql.layer.pipe(Layer.provide(SqlClientLayer));
const setup = Sql.migrate.pipe(Effect.provide(SqlClientLayer));
```

Its schema matches the current User model (first-class `email`,
`emailVerified`, `name`, `image`, timestamps) — see the
[migration guide](/guides/migration-v2/) if you're upgrading from the
attributes-bag era.

## Password hashing

`PasswordHasherLive` (PBKDF2-SHA256) and `makeScryptHasher` ship in core;
`@effect-auth/argon2` provides Argon2id over prebuilt native bindings.
`makeMultiAlgorithmVerifier` verifies legacy hashes while new ones use your
preferred algorithm — see [Multi-Algorithm Hashing](/guides/multi-algorithm/).
