---
title: Magic Link
description: Passwordless email sign-in with single-use, expiring links.
---

Magic link sign-in emails the user a single-use token; redeeming it issues a
session. The module is anti-enumeration by design: `send` succeeds uniformly
whether or not the account exists.

## Enable

Provide the service layer (with your email delivery) plus the two stores:

```ts
import { Effect, Layer } from "effect";
import * as Auth from "effect-auth";

declare const magicLinkStore: Auth.MagicLinkStore;
declare const magicLinkUserStore: Auth.MagicLinkUserStore;
declare const sendEmail: (email: string, url: string) => Effect.Effect<void>;

const magicLink = Layer.mergeAll(
  Auth.MagicLinkServiceLayer({
    expiresIn: 5 * 60 * 1000, // default 5 minutes
    sendMagicLink: (email, token) =>
      sendEmail(email, `https://app.example.com/magic?token=${token}`).pipe(
        Effect.mapError((e) => new Auth.MagicLinkError({ message: String(e) })),
      ),
  }),
  Layer.succeed(Auth.MagicLinkStoreTag)(magicLinkStore),
  Layer.succeed(Auth.MagicLinkUserStoreTag)(magicLinkUserStore),
);
```

Merge `magicLink` into the `services` you pass to `makeAuthWebHandler` and
the endpoints come alive:

- `POST /magic-link/send { email }` → always `{ status: true }`
- `POST /magic-link/verify { token }` → `AuthSuccess` + session cookie
  (invalid/expired/replayed tokens answer `400`)

## Service API

```ts
import { Effect } from "effect";
import * as Auth from "effect-auth";

declare const service: Auth.MagicLinkService;

const flow = Effect.gen(function* () {
  yield* service.send("user@example.com");
  // ... user clicks the link ...
  const { user, session } = yield* service.verify("token-from-link");
  return session;
});
```

Users are created on first sign-in (with `emailVerified: true`, since they
proved control of the inbox) unless `disableSignUp` is set. Tokens are
single use and stored server-side; `@effect-auth/sql` and the KV-backed
`MagicLinkStoreKV` layer both implement the store.
